\section{Progress Toward Midpoint Goals}
% \textit{(0.5 page)}

% Describe the progress you have made relative to the midpoint goals you set in your proposal. Be specific about what you have accomplished so far.

Our midpoint goal was to finetune an open source language mode Qwen3-8B \cite{qwen} on the FinGPT Dow30 dataset \cite{fingpt} and achieve good classification accuracy on weekly price movement. We have progressed toward that goal by experimenting with mutliple finetuning setups, each with varying precisions, LoRA ranks and hyperparameter sweeps: we implemented a full training pipeline with 8 ablation configurations spanning QLoRA (4-bit NF4, ranks 16/32/64), LoRA (8-bit, ranks 16/32/64), full finetuning in bf16, and a classification head variant. All experiments are tracked via Weights \& Biases.

Trying out different training objectives and inference pipelines, we have found the configuration that best suits our purpose for MarketMind. We have also analyzed each method in detail to figure out what went wrong and where, and then tried to resolve issues where possible within the compute and dataset budget available to us.

We found that the combined SFT + classification token objective (Method 1, detailed in Section~\ref{sec:currentstatus}) does not provide a meaningful classification accuracy. The model learns to generate an analyst style reasoning well (LM loss drops from 3.0 to 0.8) but does not learn the 12 price movement class tokens well enough (eval classification accuracy plateaus around 13--17\%, near the random baseline of 8.3\%). This result was steady for various lambda ($\lambda \in \{0.1, 0.5, 1.0, 5.0\}$) and all LoRA rank and quantization ablations.

So we have moved onto Method 2: training on the LM objective alone and pairing the finetuned model with a smaller downstream classifier that operates on the generated reasoning. This is currently in progress.



\section{Current Status}
\label{sec:currentstatus}
% \textit{(0.5-1 page)}

% Describe the current state of your project, including any concrete artifacts you have produced so far. Depending on your project, this may include experiments, preliminary results, implemented system components, datasets, evaluation pipelines, mockups, or other intermediate outputs.

For finetuning the Qwen language model on FinGPT data, there are multiple approaches that we considered. Since the training targets are both class labels corresponding to price movement from amongst 12 classes (2 directions times 6 levels of magnitude) and free text for the reasoning behind them, there are a couple of ways we can convert these into training signals. The north star for us would be classification accuracy on price movement because that is directly convertible to trading strategies. For example, if you are quite certain that the price will be up by 3-4\%, you can place orders that make a lot of money when the price is exactly in that range. However, the reasoning text serves as a great training signal for why that class might be predicted, so we want to use both of these and figure out how to combine them.


\paragraph{Method 1: } The first way we combined these 2 signals was to have the LM generate the reasoning, along with a special classification token that represents price movement. This is quite standard in classification literature \cite{lora, qlora}, by adding a dummy \texttt{<CLS>} token to the sequence and introducing new tokens for each class. Then a loss is computed by combining the regular LM loss with cross-entropy for price movement, scaled by a constant hyperparameter lambda.

\[
\mathcal{L}_{\text{total}} = \mathcal{L}_{\text{LM}} + \lambda \cdot \mathcal{L}_{\text{CE}}
\]

The results from this setup is shown in figures  Figure~\ref{fig:wandb} and Figure~\ref{fig:wandb2}. While the LM loss goes down consistently, the classification loss hovers around roughly the same range and the classification accuracy on val is also pretty constant around ~13\%. Trying a sweep of lambdas between 0.5 and 5, we get similar results. Among other ablations we try are adjusting LoRA rank between 16 and 64, and two quantization levels. We also train a full precision fully unfrozen model but that leads to an OOM error on an 80GB A100 GPU before the validation pass could run. These results lead us to 2 hypotheses - first that \textbf{rank 64 in 8bit} precision achieves the best tradeoff of precision and compute while delivering performance close to that of the fully unfrozen model. The second is that finetuning Qwen on classification loss directly is not very useful. We think it will probably require much more data since the model now needs to learn 12 brand new tokens from randomly initialized embeddings.

\paragraph{Method 2:} To achieve better classification accuracy, the next steps we plan to take consist of training Qwen 8B on the LM task only with the 8bit, 64rank configuration for longer. Then, we plan to train a separate and much smaller model DistilBERT, that takes Qwen outputs and generates class predictions. We plan to ablate this by training the classifier on (1) prompt + reasoning, (2) reasoning only, and (3) prompt only, to isolate which signal influences classification performance.

\section{Changes in Plans}
% \textit{(0.25 page)}

% Explain whether your project scope, methods, use case, or goals have changed since the proposal. If so, describe what changed and why.


Based on TA feedback that our project scope was too broad, we plan to remove the Multi agent set up mentioned initially. Instead we will use a single data collection pipeline paired with RAG over financial documents. To offset this loss of mutli agent reasoning, will use a larger thinking model with a longer context window and more sophisticated prompts at inference time.

The finetuning method also shifted. As described in Section~\ref{sec:currentstatus}, the combined SFT + classification token objective did not give us a good classification accuracy, so we pivot to a decoupled approach of SFT only finetuning for reasoning generation and then a smaller classifier downstream. 

\section{Updated End-of-Semester Goals}
% \textit{(0.25-0.5 page)}


% Describe what you now expect to accomplish by the end of the semester. If your original final goals have changed, explain your updated plan and what success now looks like.

%% We have a finetuned model, we want to put it in production - a major task now is data collection which requires us to integrate with many vendors. Parallel to that, rag that can output Fingpt's data format and serving the entire thing as a web app need to be done.

Once we have a finetuned model, the remaining work falls into 3 parts:

\begin{enumerate}
    \item \textbf{Data collection:} We need to integrate with financial data APIs such as Alpha Vantage, MarketStack, and SEC EDGAR to retrieve live news headlines, price data, and SEC filings for a given ticker. The output needs to be in the form of the FinGPT prompt for passing it directly to our finetuned model.
    \item \textbf{RAG over financial documents:} We plan to implement RAG over SEC documents such as 10-K, 10-Q, and 8-K, and also earnings call transcripts. This way, the most relevant information from these documents can be passed to the model prompt during inference.
    \item \textbf{Web application:} A UI using a framework such as Streamlit, where the user can input a company name, and then the data pipeline can fetch live data and pass it through RAG and the finetuned model to return a recommendation with reasoning.
\end{enumerate}

Success looks like: An end to end demo where a user enters a ticker/name, and the finetuned model, along with RAG to then output a well formatted and sensible recommendation which outperforms a zero shot baseline for the same input. The educational module (YouTube MCP and financial glossary) will remain a reach goal.
